# 模块：TUI 界面

TUI 基于 Textual 构建，消费 `TurnRunner` 的事件，不直接执行工具或调用模型。实现位于 `lancher_code/tui_views/`。

## 组件职责

| 文件 | 内容 |
|---|---|
| `chat.py` | 主界面、事件消费、输入回执、队列调度、设置运行时回调 |
| `theme.py` | 共享深浅主题、语义颜色与主题切换 |
| `composer.py` | 可持续编辑的输入框、中文意图及命令补全 |
| `chat_controls.py` | 阶段栏、待发送队列、计划预览、策略选择与队列编辑 |
| `message.py` | 消息角色、增量更新与按发生顺序排列的正文、思考段和工具组 |
| `timeline.py` | 顺序记录映射、轻量折叠、工具组与每次调用的状态和详情 |
| `permission.py` | 按请求 ID 返回结果的非阻塞内联审批 |
| `settings.py` | 模型、MCP、权限、外观与输入目录；每个编辑单独提交 |
| `model_settings.py` | 供应商连接、模型继承与覆盖、独立默认选择 |
| `model_picker.py` | 按供应商、API 模型名及显示名搜索，区分本次／默认 |
| `bootstrap.py` | 连接供应商 → 第一个模型 → 确认并启动 |

## 输入与事件

普通 Enter 在空闲时提交；工作期间根据 `busy_enter_action` 排队、补充或保留草稿。输入只有在取得接受回执后才清空。工作期间斜杠命令保留在草稿中，不作为用户文本发送。

`assistant_message_completed` 仅表示一个消息段结束；只有 `turn_completed` 表示整个任务成功，可启动下一条 FIFO 消息。失败、取消和恢复会话后均暂停队列，用户需明确继续。队列编辑使用独立编辑器，不覆盖输入区的新草稿。

`permission_request_created` 挂载面板后立即返回事件循环；决议通过 `resolve_permission_request()` 提交。`permission_request_closed` 使面板失效并恢复焦点，不依赖用户作答才能响应取消。补充会撤销旧审批；已启动操作完成后才继续。

事件消费者使用 `aclosing` 保证异常或关闭界面时收拢生成器；卸载界面会等待 `stop_and_wait()`，避免后台命令的资源回收被拖到事件循环关闭之后。

阶段、模型和策略在工作、压缩、等待审批期间均由服务层拒绝变更。`Shift+Tab` 循环工作阶段，策略通过 HUD 或 `/permissions` 选择。计划执行携带当前会话 ID 与内容摘要；服务层验证快照并冻结正文，界面提交一次真实执行请求。

## 阅读与布局

正文使用连续文本及角色标记。“你”和“LanCher”采用同一左边界、无边框布局，名称均以主题强调色加粗；失败或取消时保留名称，在名称后补充状态，失败标记使用错误色。同一条回复内按实际发生顺序排列思考、工具调用与正文；中间说明留在发生的位置，最后的正文自然形成总结，不把思考或工具重新收集到专属区域。工具记录与思考显示开关相互独立。助手正文支持 Markdown，包括标题、列表、链接、行内代码与代码块；用户输入和工具结果按原文显示。

思考不显示额外标题，使用灰色文字：输出时默认展开，结束后收成首个非空行加省略号，点击或聚焦后按 Enter／Space 可展开。纯空白增量不生成折叠入口；展示时移除首尾和摘要之后多余的空白行，正文内部段落与原始记录保持不变，摘要按终端字符宽度截取。流式增量和后续区块保持原控件及手动展开状态；用户已主动折叠的输出段不会被下一次增量打开。

同一次模型响应中的工具调用组成一组。执行期间展开组内所有调用，同时显示排队、执行、等待批准、完成、失败、停止或跳过等各自状态；实际并发关系由工具执行器决定。每条调用使用终端单色符号和简短名称，独立展开参数与完整输出，点击单条详情不触发父组折叠。全部正常完成后，整组默认收成“已执行 N 个工具”；单个工具省略父组标题，直接由这一条调用展开详情。失败与等待批准保持可见，不能被正常完成摘要掩盖。

用户仅在底部时跟随新消息，阅读历史时不抢滚动。手动展开单条调用时，组完成不会将正在查看的详情自动隐藏；仍可手动收起整组，重新展开后保留各条详情状态。整个任务成功结束（`turn_completed`）后，将该任务全部消息段中的思考、工具组和单条详情统一折叠一次，使总结成为阅读重点；消息段结束不触发这次收起。更早任务的阅读状态不受影响，成功后重新手动展开也不会被刷新或重复完成事件再次关闭。失败、取消与等待审批保持问题可见；恢复已完成消息时默认折叠。被拒绝或未实际启动的调用显示“未执行”，不计入“已执行”的数量。展开内容通过聊天区域滚动访问，不挤占输入区；折叠标题具有独立键盘焦点，Enter／Space 与点击使用相同交互。

“聚焦主区”采用终端原生样式：字体族、字号与行距由终端管理；界面使用字重、主题前景色、少量底色、字符缩进和整行间距建立层级。标题与关键内容使用正文色加粗，说明和快捷键使用次要色；强调色用于角色名称、当前阶段和主要动作，键盘焦点使用反色。状态同时带文字或标记，不只依赖颜色。Markdown 标题、引用、行内代码和深浅主题共用配色，代码块按主题切换语法配色和背景，未知语言同样沿用应用配色。

聊天主区最多 112 列，设置最多 104 列，首次配置最多 76 列；宽终端居中，窄终端按可用字符宽度排版。聊天正文采用统一前景色，过程文本用灰色降低权重；相邻思考和工具组不另插空行，过程与正文之间、两条消息之间各保留一行，展开的工具详情不重复叠加上下留白。按时间顺序排列后仍通过留白、缩进与少量字重把阅读重点留给正文，不增加大标题、彩色卡片或常驻边框。设置将“本次对话使用”和“新对话默认”压成两行摘要，供应商与模型目录紧随其后。目录调整尺寸时保留选中项与展开状态。

HUD 分别展示模型、阶段、策略、预计上下文和任务状态。累计用量、缓存用量、MCP 状态放在详情，不推断没有真实数据的耗时和百分比。窄屏优先保留输入、阶段与待处理状态；长内容通过滚动和焦点导航访问。

## 设置提交

`SettingsService` 按模型、界面偏好、MCP 作用范围、权限作用范围提交。模型保存不写 MCP 和权限文件。已提交快照与草稿分离；保存 A 后取消 B 不会撤销 A。

模型保存回调刷新运行时，默认变更不替换本次模型；本次切换失败保留旧模型。配置落盘成功而运行时应用失败分别提示。MCP 保存后持续显示待重启。首次配置最终确认前不写文件，返回上一步保留输入。

## 验证入口

`tests/test_tui_*.py` 通过模拟 Provider 和 Textual Pilot 验证交互，`tests/test_task_interaction.py` 验证任务边界。`tests/test_tui_timeline.py` 验证交替输出顺序、自动与手动折叠、组内多工具状态、独立详情、单工具一层折叠、失败／审批可见和历史阅读位置。`tests/test_tui_message_polish.py` 验证角色名称高亮与对齐、过程及正文间距、跨消息段的任务完成折叠、恢复默认状态及失败／取消时的问题可见性。测试覆盖深浅主题、100×40／60×24／32×16、长参数与完整结果、键盘展开、队列操作和审批期间取消。
