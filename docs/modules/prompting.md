# 模块：提示词构建与请求前缀

提示词模块组织主机规则、项目约定、Skills、工具目录与对话。基础身份为“AI 编程助手”，不绑定产品名称、终端或具体界面；系统环境仍作为真实工具执行上下文提供。请求前缀由智能体核心保存和更新，界面只展示估算与提交操作。行为规则要求在授权范围内主动调查、实施和验证；答复长度随任务与用户要求调整，只在缺少关键信息、授权或必要取舍时提问。

## 固定前缀和尾部事件

`context/prefix.py` 为当前请求周期建立一个固定系统前缀：基础行为规则、通用宿主规则、全局 Skills 候选目录，随后是初始项目约定、项目 Skills 目录、项目执行环境和 MCP 索引。工作目录、操作系统及项目说明不会出现在全局目录之前；共享部分不依赖项目和会话状态。首次请求记录当前日期、阶段、权限与技能状态；后续变化追加成带 `source="host"`、`epoch`、`seq` 的 `<host_update>` 尾部记录，不反复改写旧用户消息。

```text
同一周期的系统前缀 + 已有对话 + 已有主机事件
  → 新用户任务 / 新工具结果
  → 有变化时追加 host_update
  → 下一次模型请求
```

主机事件可携带新 Skill 正文、项目 AGENTS.md 更新、技能和 MCP 目录变化、阶段与权限变化；间隔较长时补充时间。它是核心状态事实，不是新用户任务，不增加权限。模型使用同字段最新值，执行器仍按实时状态校验阶段、工具身份和权限。

全局与项目目录只描述候选库存，不因会话禁用或同名覆盖而重新生成全局内容。`skills_state` 在尾部主机事件中提供完整禁用快照和目录中全局项的项目覆盖关系；仅允许用户显式调用的覆盖目标列在 `explicit_only` 中，不能自动触发或回退全局来源绕过。空列表也会发送，以明确清除旧状态。项目同名技能默认优先，完整 `user/<名称>` 仍可显式指定；禁用由加载和资源读取工具实时拒绝。

协议无关历史用 `control_kind="host_update"` 明确标识宿主事件；用户原文保持未标记，即使引用同名标签也不升级为主机记录。为兼容接口，尾部状态仍可由 `user` 角色承载，但固定主机规则与事件正文明确其来源和含义。前缀校验使用登记的锚点、正文和类型，压缩不会把这些事件当成真人用户目标或新的用户轮次。进程通知使用独立 `process_notification` 类型。

技能正文不放在加载工具的结果里。`load_skill` 把正文快照交给核心，核心追加主机事件；跨轮继续复用正文和已有事件。项目约定通常在周期初始前缀中，后续文件更新也通过尾部事件提供。

## 请求周期的重建

| 条件 | 行为 |
|---|---|
| 新 Skill、AGENTS.md 更新、目录或阶段／权限变化 | 在当前周期追加主机事件 |
| 新 MCP 工具被发现 | 常规模式加入 `tools`，保留已发现定义与顺序；实验模式投影原生追加事件 |
| Skill 正文卸载、禁用、缺失或需要真正回收 | 重建前缀，清理旧正文事件 |
| 压缩成功、模型／协议／窗口切换、实验模式切换 | 重建周期，采用新基线 |
| 内置提示词版本变化 | 下次正式请求重建周期，保留用户与工具历史，采用新版稳定规则 |
| 压缩失败、取消或提交回滚 | 保留原前缀、历史与技能状态 |
| HUD 预览估算 | 在副本上计算，不提交新事件或改变周期 |

`SessionController` 持久化前缀状态、已发现工具及事件位置。正式请求准备后才提交状态；恢复会话时保留历史顺序，不重放远端操作。原生 OpenAI 模式移除或同名替换工具时也会重建，因为该追加协议只支持增加定义。

## 大量 Skills 的首轮请求

Skill 数量不等于工具数量。首轮只发送名称、来源和描述构成的目录，不发送所有 SKILL.md 正文，也不为每个 Skill 创建独立工具。两类目录总预算是 `max(512, min(8000, context_window // 10))` 字符；128k 窗口最多 8000 字符。全局目录固定最多使用总预算的一半，保证其不随项目变化，同时为项目保留空间；项目使用剩余额度，包括全局未使用的部分。超过预算时附明确省略提示。仅允许显式调用的技能不进入候选目录；被项目覆盖或本会话禁用的全局项仍保留元数据，通过尾部状态说明实际可用情况。未列出的已登记技能仍可由用户用完整 ID 显式指定，当前没有模型侧的全量 Skills 搜索工具。

模型调用 `load_skill` 后，只有所选正文作为下一条主机增量加入；系统前缀和旧消息保持不变，加载工具结果只保存确认信息。后续保持已加载正文，直到卸载或压缩回收；引用资料继续按需读取。详见 [Skills](skills.md)。

## 常规与实验工具方式

默认使用常规 `tools` 数组。MCP 延迟工具通过 `tool_search` 加载，完整参数定义从下一次请求开始进入数组，并跨用户轮保留。能力目录有字符预算，未列出的已注册工具仍可搜索。

阶段和审批变化通过主机事件告知模型，已发布的工具 Schema 保持可见；定义可见不代表当前允许执行，执行器仍按最新阶段和权限拒绝违规调用。末轮或其他禁止继续调用工具的请求保留定义，使用 `tool_choice: none` 禁止调用，避免通过清空工具数组改变已有前缀。

系统设置中的“原生 MCP 工具追加”实验项默认关闭。它让核心保存的工具变更由 Provider 投影为端点的原生协议，不改成通用 `mcp_call` 代理：

- OpenAI 使用 Responses 与 `additional_tools`；要求端点接受该请求方式。
- Claude 使用 `inline-tools-2026-09-15` beta 的 `tool_addition`／`tool_removal`。

不支持的端点明确报错并提示关闭实验项，客户端不自动重放操作。设置变化在空闲时校验、保存并应用，下次请求重建周期。具体配置见 [配置说明](../configuration.md)。

## 缓存边界

稳定前缀和追加事件减少已有请求内容的变动，为供应商缓存提供条件，不保证实际命中率。

前缀状态持久化 `shared_system_count`，标识通用规则与全局目录结束的位置。正式请求、预览及恢复沿用同一边界；项目状态与按需加载的正文在边界后，不为新技能重排已经发送的内容。协议缓存也包含工具定义；工具、推理参数或供应商缓存条件变化仍可能影响命中。

官方 Anthropic 端点默认发送 `cache_control`；Claude 兼容端点只在开启实验项、由用户声明支持时发送。启用时系统字段按内容块发送，在共享部分末尾设置显式缓存点，同时保留请求末尾自动缓存以复用增长中的对话。关闭时不发送缓存字段。

普通 OpenAI Chat Completions 保留兼容请求结构，由端点自行处理缓存。Responses 仅在绑定当前连接的模型元数据明确声明 `capabilities.prompt_caching.explicit_breakpoints.supported=true` 时，向共享内容块发送 `prompt_cache_breakpoint`，保留默认隐式对话缓存。这个字段是本应用接受的兼容模型列表扩展，不是所有 `/models` 接口必然提供的标准字段；未知或不支持时不发送，不按品牌、域名或模型名猜测。详情参见 [OpenAI 缓存规则](https://developers.openai.com/api/docs/guides/prompt-caching) 与 [Claude 缓存规则](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)。

当前验证使用离线 Provider 传输 fixture，检查请求结构、流式工具结果与错误处理；尚未做真实模型 API 的兼容性或缓存命中率实测。真实请求用量仍由 usage 账本按上报值记录，不能把前缀稳定等同于已节省费用。

## 实现职责

| 入口 | 职责 |
|---|---|
| `context/prompts.py` | 基础角色、环境、阶段提示和有预算的 MCP 索引 |
| `context/prefix.py` | 固定前缀、增量主机事件、工具基线和重建条件 |
| `context/request.py` | 在副本上准备请求，投影历史和工具事件 |
| `sessions/controller.py` | 正式请求状态提交与只读预览，保存和恢复 |
| `agent/capabilities.py` | 项目约定与技能内容提供器 |
| `agent/skill_context.py` | 技能激活与正文／引用状态 |
| `providers/native_tools.py`、`responses.py` | 把核心工具事件投影到支持的端点协议 |

讨论和计划阶段的只读边界、Session workspace 及计划确认依然由核心执行；模型不能自行切阶段或提升权限。旧周期重建只清理应用登记的宿主事件，用户提供的同名标签和多段消息保持原文。

进程完成摘要仍是后台事实，附在后续正常任务中，不因后台输出自动启动新任务。新规则与技能也不自动执行脚本。相关生命周期见 [Skills 与项目约定](skills.md)、[上下文压缩](../workflows/context-compaction.md)。
