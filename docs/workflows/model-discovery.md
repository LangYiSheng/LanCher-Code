# 供应商模型发现与能力信息

实现位于 `providers/discovery.py`、`providers/metadata.py` 和 `tui/model_discovery.py`。模型发现与对话生成分开，前者不发送用户对话、不调用模型生成，也不计入生成用量。

## 两种协议

- OpenAI 使用 `{base_url}/models`，认证为 `Authorization: Bearer`，读取 `data[]` 的模型 ID、归属和创建时间。[标准接口](https://developers.openai.com/api/reference/resources/models/methods/list)没有规定推理能力字段；端点有能力扩展时再读取，没有时保持未知。
- Claude 使用对应的 models 接口及 `x-api-key` 认证。根基址按协议补 `/v1`，已有挂载路径保持不变；例如 `/v1`、`/custom/v1` 都只追加 `/models`。按 `has_more / last_id / after_id` 获取后续页。[标准接口](https://platform.claude.com/docs/en/api/http/models/list)可声明 thinking 类型、effort 支持情况及输入输出上限。

API 基址应指向对应协议的接口目录。聊天接口兼容不保证模型列表也已实现；列表端点不存在时保留手动添加入口，不尝试改用另一种协议的认证，也不根据品牌切换地址。

## 统一信息

`ModelMetadata` 保存 API ID、显示名称、归属、创建时间、获取时间、模态、窗口及输出上限，以及 `ModelCapabilities`。未知值为 `None`，明确没有能力为 `()`。

除标准 Claude 字段外，接受模型条目中通用的 `effort.supported_levels / default_level` 与 `supported_endpoints` 扩展，不检测供应商品牌。归属与显示名称只用于呈现，不参与协议或能力推断。

能力快照通过连接指纹绑定协议、完整基址和实际认证身份，并核对 API 模型名。指纹不保存密钥原文；配置里的环境变量引用继续保留。连接或模型名变化后，旧信息不适用于新请求。请求的 model 与 provider 配置不同也不能复用旧模型能力。

## 交互与保存

供应商保存后自动开始发现，也可在草稿阶段先发现再选中模型一次保存。查询在后台进行，返回的模型可逐个勾选或全选。筛选不丢失已选的隐藏行；全选覆盖全部可加入模型，已经加入的同源模型不会重复加入。模型归属和 API ID 在目录及发现界面中呈现，模型名称中的 Markdown 字符不会被当成样式。

已有模型刷新只改变同源 metadata；稳定 ID、手动显示名、连接覆盖、上下文及输出额度、当前会话模型和默认模型都保留。会话 effort 由 `/effort` 选择；能力刷新后不支持的档位恢复 auto。独立连接下的同名模型不是同源模型，不会被父供应商发现覆盖。

首次配置复用同一多选界面，将多个选中模型一起保存，明确显示首个对话模型和模型数量。取消发现仍可手动配置。

编辑连接、切换设置页、关闭界面或返回上一步会使旧操作失效；完成后再次核对草稿和界面版本，过期结果不加入当前目录。网络取消会关闭客户端，不缓存未完成的分页。

## 缓存与失败

会话内列表缓存默认 24 小时，按连接指纹隔离；主动刷新绕过有效期。缓存只保存完整且解析成功的模型列表。若刷新因连接、响应格式或服务错误失败，可显示明确标记的旧结果；认证失败直接提示，不复用缓存可见性。

每页最大响应 4 MiB，总模型数最多 10,000，最多 100 页；游标重复、缺少后续页游标或超出限制时明确失败，不把部分列表当成完整结果。无效身份条目被计数并明确提示，重复 API ID 去重。HTTP 错误不回显远端正文，避免把端点返回的认证内容显示在设置页。

加入后的 metadata 持久化为离线快照，获取时间保持原样。发现缓存有效期与持久化快照寿命不同：后者直到再次发现或连接变化前可使用，界面不会宣称它是刚刚查询的结果。

## 请求策略

支持 adaptive 的 Claude 能力声明触发自适应推理；只有旧版 enabled 声明时自动分配接口所需额度。effort 的发送字段按协议确定，未声明默认档位就省略，不猜测某个型号默认应该是 high 或 medium。

OpenAI 接口形式由 `api_mode` 或已声明的 `supported_endpoints` 决定。标准聊天、兼容聊天和 Responses 分别使用 `max_completion_tokens`、`max_tokens` 和 `max_output_tokens`。没有接口声明时 auto 回退到兼容聊天，可在设置中明确选择 Responses。用户输出额度始终是实际发送的总上限，已声明的输出上限也参与校验。

原始思考内容、签名、工具交换、自动续接和摘要完整性检查仍由原有协议与会话模块负责，metadata 不写入用户对话。
